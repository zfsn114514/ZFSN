## 0. 总则：这些指南管什么

指南描述 Bing **如何发现、抓取、建立索引、评估与呈现内容**，覆盖范围是：

- Bing 搜索结果
- Copilot
- Grounding API 结果

遵守指南可以让 URL 具备以下资格：

| 资格 | 含义 |
|---|---|
| 索引与排名 | 能进入搜索结果 |
| Grounding 结果与引用 | 能被 AI 回答引用为来源 |
| 持续曝光与有效流量 | 长期可见性 |

**不遵守的后果（原文明确写出）：**
- Bing 搜索中可见性下降
- Grounding 体验资格下降
- **从 Bing 索引中除名（delisting）**

## 1. 内容质量：清晰、聚焦、有用

### 1.1 内容本身应满足（第 11 条）
Grounded 回答与引用依赖 Bing 能**清晰解读并核实**的内容。结构良好、准确、聚焦的内容能提升检索质量、grounding 可靠性与引用准确度。

内容应当：
- **完整满足用户意图**
- **原创且具备权威性**
- **无需外部上下文即可读懂**

> ⚠️ **内容单薄（thin）、广告堆砌、或纯联盟营销（affiliate-only）的 URL，可能失去排名资格与 grounding 曝光。**

### 1.2 内容可独立核实（第 15 条）
内容能**独立成立**的 URL，更容易被选中作为 grounding 来源和引用。要求：
- 事实与定义**显式写出**，不要依赖读者推断
- 关键表述**不依赖隐含内容**
- 重要信息**就在该 URL 页面上可见**

### 1.3 实体定义清晰一致（第 16 条）
人物、组织、产品、地点的命名要**清晰且一致**：
- 避免有歧义的指代
- 清晰的实体定义提升 grounding 可见性与引用准确度

### 1.4 每个 URL 只聚焦一个主题（第 17 条）
聚焦单一主主题的 URL 更容易被选为 grounding 结果：
- **避免在同一个 URL 混入不相关概念**
- 标题、各级标题、内容意图要**对齐**

### 1.5 关键信息前置（第 18 条）
- 把核心信息放在页面**靠前位置**
- **避免冗长铺垫**后才进入正题
- 前置清晰度提升 grounding 可见性与可靠性

### 1.6 内容准确且及时更新（第 19 条）
事实或指引变化时要更新内容：
- 合理使用新鲜度信号
- **删除或修订过时信息**，防止错误信息被呈现
- 内容新增 / 更新 / 删除时通过 **IndexNow** 通知

### 1.7 图片与视频服务于「理解」（第 12 条）
图片和视频应当**强化页面正文**，而**不应成为理解主题的唯一信息来源**。

应提供：
- 描述性的文件名
- Alt 文本
- 字幕、转录文本或结构化数据

### 1.8 HTML 结构清晰（第 13 条）
遵循以下最佳实践：
- `<title>` 与 meta description
- 逻辑正确的 `<H1>`–`<H6>` 层级
- 语义化 HTML 元素

> ⚠️ **标题标签与 meta description 缺失、重复或过短，会降低索引可靠性、排名，以及获得 grounding 结果与引用的资格。**

### 1.9 结构化数据要准确（第 14 条）
- 结构化数据**可能**帮助更清晰的 grounding，但**不保证**可见性或流量
- 标记必须**准确反映可见内容**

## 2. 站点结构与导航

### 2.1 用链接建立结构与权威（第 5 条）
每个重要 URL 都要能**通过可抓取的内部链接到达**。

链接应：
- 使用标准 `<a href>` 链接（不要用 JS 伪链接）
- 包含相关的**锚文本**或图片 alt 属性

> 强健的内部与外部链接支撑发现、权威评估和 grounding 资格。

### 2.2 站点结构逻辑化（第 21 条最佳实践）
- 保持站点结构**逻辑清晰、可达**
- 用 robots.txt 屏蔽**不必要的抓取路径**

## 3. URL 规范、去重与迁移

### 3.1 让 URL 容易被发现（第 2 条）
确保 Bing 能通过以下方式稳定发现你的 URL：
- **IndexNow** URL 提交
- **XML sitemap**
- 可抓取的**内部链接**
- 来自相关站点的**外部链接**

### 3.2 合并重复 URL（第 6 条）
- **避免同一内容出现在多个 URL**
- 重复 URL 会稀释信号，降低 Bing 为 grounding 结果或引用挑选 URL 的信心
- 使用**规范 URL（canonical）**、参数控制、一致的 URL 结构来合并信号

### 3.3 URL 迁移用正确的重定向（第 7 条）
内容迁移时：
- 永久性变更用 **301** 重定向
- **302 仅用于极短期变更（少于 2 天）**
- **用重定向而不是 canonical 标签**（来处理迁移）

### 3.4 内容删除要清理干净（第 9 条）
内容被永久移除时：
- 返回 **404 状态码**
- 适当使用 Bing 的内容移除工具
- 通过 **IndexNow** 更新已删除或变更的 URL

### 3.5 保持 URL 长期稳定（第 20 条）
- 不要进行不必要的 URL 变更
- 必须变更时：使用正确的重定向，**保留原意与意图**
- 稳定的 URL 支撑长期可见性与连续性

## 4. 抓取与索引

### 4.1 允许高效抓取与渲染（第 8 条）
让 Bingbot 能高效抓取并渲染内容。

**要避免：**
- 不必要地屏蔽重要 URL
- 把关键内容**藏在客户端渲染（client-side rendering）之后**
- 渲染内容需要**过多或不必要的 HTTP 请求**
- 输出大量**低价值 URL**（如重复内容、带大量参数的 URL）
- **在 robots.txt 中屏蔽 Bingbot**

> ⚠️ **无法被可靠渲染的内容，可能不会被抓取索引，也不会被选入 grounding 结果。**

### 4.2 用 sitemap 传递重要性与新鲜度（第 3 条）
Sitemap 应当：
- **只列规范 URL（canonical）**
- 反映**当前**站点结构
- **及时移除**已删除或已重定向的 URL
- 在适用时包含新鲜度信号（如 `lastmod`）

> Sitemap 不保证可见性，但显著提升索引准确度与新鲜度。
> 准确的 `lastmod`、以及 `ETag` 等 HTTP 校验头，能帮助 Bing 更可靠地检测内容变化。

### 4.3 URL 变化时快速通知（第 4 条）
以下情况用 **IndexNow** 通知 Bing：
- URL 新增
- 内容更新
- URL 移除

> 及时通知能让 Bing 刷新索引，减少 Copilot 回答与 grounding 结果中引用过时/错误 URL。
> **尽量避免批量提交**——流式（streaming）提交更新更快、降低服务器负载、提升索引准确度。

### 4.4 正确使用 robots.txt 与 meta 指令（第 10 条）
- **robots.txt 控制的是抓取权限，不是索引。**
- 要让 URL **不出现**在 Bing 搜索、Copilot 体验或 grounding API 结果中，应使用 **NOINDEX**。

**展示层面（影响摘要/引用外观）：**
- `DATA-NOSNIPPET` / `NOSNIPPET` 会阻止 Bing 显示摘要文字，并可能**降低 Copilot 引用质量**
- 想控制 Bing 可以展示或引用的文本，用 `data-snippet` 属性指定允许的内容

**Grounding 层面（影响 AI 引用深度）：**
- `NOARCHIVE` 会阻止内容被用于 Copilot 回答和 grounding 结果
- `NOCACHE` 会让 Copilot 只能使用 URL、标题和摘要片段，**降低引用深度与回答质量**
- 若希望内容被 Copilot / grounding 使用，**避免对这类内容使用 NOCACHE**

### 4.5 控制抓取效率、减少抓取浪费（第 21 条）
Bing 依据**站点健康度、效率、信号质量和抓取价值**分配抓取配额。
过度的抓取浪费、重复或低价值 URL，会直接限制索引、延迟发现、降低重要内容的 grounding 可见性。

**低价值 URL / 重复 / 抓取浪费会导致：**
- 重要内容的索引被延迟
- 优先 URL 的 grounding 可见性下降

**最佳实践：**
- 消除重复或低价值 URL
- 一致地使用 canonical 化
- 用 robots.txt 屏蔽不必要的抓取路径
- 保持站点结构逻辑清晰、可达

### 4.6 抓取效率、可见性与「超越点击」的衡量（第 22 条）
内容可能**无需传统点击**就出现在 Bing 各类搜索体验中。
- 内容可能以**曝光（impressions）、引用（citations）或 grounding 参考**的形式出现在 Copilot 回答中
- **点击量下降并不一定意味着可见性丧失**

**应监测：**
- 曝光量（Impressions）
- 索引状态（Indexing status）
- Grounding 与引用资格（Grounding and citation eligibility）

## 5. SEO 基础与 AI 时代的关系（第 1 条）

Bing 与 Copilot 的搜索体验，**依赖与传统搜索相同的抓取、索引与排名基础**。
支撑发现、索引准确性与内容清晰度的 SEO 最佳实践，同样支撑 AI 体验、grounding 结果与引用的资格。

**这些做法支撑：** 抓取效率、索引准确性、URL 合并、内容清晰度与结构、权威与信任信号。
**也因此支撑：** grounding 结果资格、跨 Bing / Copilot / AI 搜索体验的长期可见性。

> 关于 SEO 与 GEO 的关系：SEO 提升网站的技术质量、清晰度与可访问性；**GEO（生成式引擎优化）聚焦内容在 AI 回答中被 grounding 和引用的资格**。
> SEO **不保证**排名或流量，GEO **不保证** grounding 或引用。

## 6. 禁止的作弊行为（Abuse and Examples of Things to Avoid）

以下做法属于**操纵性、误导性或低质量行为**。涉及的站点可能面临：
排名下降、grounding 可见性被压制、失去 grounding 资格、结构化数据被忽略，**或被从 Bing 索引中移除**。
Microsoft 可对欺骗或滥用行为采取行动；若属误判，可通过 Bing 网站管理员工具联系支持。

### 共 10 类：

| # | 行为 | 关键要求 |
|---|---|---|
| 1 | **Cloaking（伪装）** | 向搜索爬虫和用户展示不同内容属操纵行为。不得对爬虫与访客提供实质不同的体验。 |
| 2 | **Link Schemes and Artificial Promotion（链接方案与人为推广）** | 操纵入站链接以抬高权威违反指南，包括**买链接、垃圾链接、私有网络（PBN）、以及模拟热度的人为社交推广**。链接应通过高质量有用内容自然获得。 |
| 3 | **Duplicate Content Across Multiple URLs（跨 URL 重复内容）** | 同一或高度相似内容发布在多个 URL，会降低 Bing 选择首选版本的信心。**从源头通过 URL 管理与结构解决**；canonical 标签只能提示偏好，**不能替代修复根本问题**。 |
| 4 | **Scraped or Republished Content Without Added Value（无增值的抓取/转载内容）** | 复制他人内容且不增加原创价值，对用户无益且可能违反版权预期。**仅做修改或轻度改写、没有新见解或视角，同样视为抓取（scraping）**。要创作原创、有差异化的内容。 |
| 5 | **Keyword Stuffing and Artificially Engineered Language（关键词堆砌与人为编造语言）** | 内容应为人而写，而非为操纵排名系统或触发引用/AI 回答。**过度重复、不自然措辞、堆砌不相关关键词**会降低可见性甚至被移除。 |
| 6 | **Automatically Generated Content at Scale（大规模自动生成内容）** | 无监督、无质量控制、无编辑审核的大规模生成内容，通常缺乏有用性、准确性与原创性，**可能被排除索引**。 |
| 7 | **Affiliate Programs Without Sufficient Value（无足够价值的联盟营销）** | 主要作用是把用户导向零售商的站点，**若不提供原创价值**（如独特评测、对比、分析），可能降低可见性甚至被移除。 |
| 8 | **Malicious Behavior（恶意行为）** | 参与钓鱼、恶意软件分发等有害活动的站点，面临降权或移除风险。**维护基础设施安全、管控发布权限是必要的**。 |
| 9 | **Misleading Structured Data（误导性结构化数据）** | 结构化数据必须准确反映可见内容。不相关、不准确或误导性的标记**可能被忽略**，并影响信任与增强功能的资格。 |
| 10 | **Prompt Injection and AI Manipulation（提示注入与 AI 操纵）** | 添加旨在**操纵或干扰 Bing / Copilot 所用语言模型**的内容，可能导致可见性下降或被移出搜索结果。 |

## 7. 一句话总纲（对本站最有操作性的几条）

1. **内容为王且要能独立成立** —— 原创、准确、显式、单一主题、关键信息前置。
2. **URL 唯一且稳定** —— 重复内容从源头修，迁移用 301，删除返回 404。
3. **让 Bingbot 抓得到、渲染得出** —— 不要在 robots.txt 屏蔽，不要把正文藏在客户端渲染后面。
4. **sitemap 只列 canonical，lastmod 要准；内容变动用 IndexNow 通知。**
5. **想被 Copilot 引用，就别用 `NOCACHE` / `NOARCHIVE`。**
6. **十类作弊行为不要碰**，尤其是伪装、链接方案、跨 URL 重复、爬取转载、关键词堆砌、规模化自动生成、提示注入。

## 附：对本站当前情况的对应关系（供参考）

- 已在 sitemap 中列出的页面需确认**只含 canonical URL**，且 `lastmod` 准确（第 3 条）。
- 站点若存在不带 `www` 的变体，需确认其行为一致（否则构成「实质不同体验」的隐患，也影响 URL 合并，见第 6 条）。
- 内容变动（如 PvZ 页面更新）后可通过 **IndexNow** 主动提交（第 4 条）。
- 页面若有 `NOCACHE` / `NOARCHIVE` 需复核，避免影响 Copilot 引用（第 10 条）。
- 游戏页 `/pvz/pvz-portable.html` 属交互式内容，需确保有**可被渲染的文本内容**（第 8 条），否则可能被判为无法可靠渲染。
