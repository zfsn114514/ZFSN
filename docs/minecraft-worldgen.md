# 方块世界 2D · 地形生成重写交付说明

> 目标：把网页版 2D Minecraft 的地形生成从「一张 4096×256 的平坦地图」重写成
> **无限世界 + 多生物群系 + 洞穴/矿石/结构**，观感尽量贴近 Java 版。
>
> 本文件是交付说明：改了什么、核心逻辑怎么走、每一项验收怎么测的、数据是多少。
> 想调参数看 [§4 参数表](#4-参数表在哪)，想跑验收看 [§3 验收清单](#3-验收清单规格书-12)。

---

## 1. 总体架构

### 1.1 两层结构：生成逻辑与渲染彻底分离

```
minecraft/
├─ worldgen/            ← 纯逻辑层：零 DOM、零 Canvas、可被 node 直接 import
│  ├─ constants.js      ← 所有可调参数（世界类型、噪声频率、矿石表、 cave 阈值…）
│  ├─ rng.js            ← 种子哈希：toSeed / mixSeed / hash1 / hash2 / rand01
│  ├─ noise.js          ← 一维/二维梯度噪声 + fBm
│  ├─ biomes.js         ← 群系注册表 + 气候采样 + 群系划分
│  ├─ terrain.js        ← 高度模型 + 地层（草/土/石/深板岩/基岩）+ 海底 + 雪冰
│  ├─ caves.js          ← 蠕虫 / 大空洞 / 竖井 三种洞穴（纯谓词）
│  ├─ ores.js           ← 矿脉团块（三角分布 Y、椭球团块）
│  ├─ decorations.js    ← 树木 / 草花 / 仙人掌 / 睡莲 / 海草海带 / 南瓜西瓜
│  ├─ structures.js     ← 废弃矿井 / 简化村庄
│  ├─ chunk.js          ← 区块存储：Uint16Array + 调色板下标
│  └─ worldgen.js       ← 调度器：按需生成 / 卸载 / 存档差异 / 出生点
├─ worldbridge.js       ← 适配层：worldgen（名字 + y 向上）↔ 游戏（下标 + y 向下）
├─ game.js              ← 游戏层：渲染、输入、战斗、背包、流体接线
└─ tests/               ← node --test 可跑的纯逻辑测试
```

**纯逻辑层为什么重要**：地形生成的全部规则都能在 node 里跑，不需要浏览器，
所以「同种子同坐标必然同结果」「乱序生成不串味」这类性质可以被**逐格断言**，
而不是靠肉眼看。

### 1.2 ★ 坐标系：游戏 y 向下，worldgen y 向上

这是本次重写里最容易出错、也最需要说清楚的一点。

| | y=0 | y 增大方向 | 海平面 | 底部 |
|---|---|---|---|---|
| **游戏**（2D 侧视，重力 +y） | 天空 | 向下 | 192 | 255 基岩 |
| **worldgen**（Java 约定） | 基岩 | 向上 | 63 | 0 基岩 |

两者关系固定为 `gameY = 255 - wgY`。所有跨层访问都必须走 `worldbridge.js` 的
`toGameY()` / `toWgY()`，不能直接用 worldgen 的 y。

> 为什么不把 worldgen 改成 y 向下？因为整套 worldgen 与它的测试都是按「y 向上」
> 写的（这也是 Java 版与任务书的约定），倒过来要重写 8 个文件、几百行、并把
> 二十多项测试全部翻面 —— 收益远小于风险。适配层把差异收在一处，风险最低。

### 1.3 无限 X 与分块

- X 轴无限，安全范围 ±2²⁵（`SAFE_X`）；摄像机与渲染范围**不再夹在 [0, W] 里**，
  接近边界时调试面板给出提示。
- 区块宽 16 列、高 256（整列），状态机 `EMPTY → TERRAIN → CARVED → DECORATED → FULL`。
- 存储是 `Uint16Array(16×256)` 的**调色板下标** + 并行的 `Uint8Array` natural 标记，
  **没有任何「每格一个对象」的嵌套数组**（规格书 §9 明确禁止）。
- 按需加载：玩家左右各 `RENDER_DISTANCE=8` 个区块；每帧最多生成
  `MAX_CHUNKS_PER_TICK=1` 个区块、累计不超过 `WORLDGEN_BUDGET_MS=4` ms；
  超出 `UNLOAD_DISTANCE=12` 的区块卸载（被玩家改过的存进差异表）。

### 1.4 确定性怎么保证

- 所有特征都是 **绝对坐标 + 种子** 的纯函数：坐标哈希 `hash2(seed,x,y)` / `hash1(seed,x)`，
  不用 `Math.random()`，不用全局序列 RNG。
- 噪声按用途取不同子种子（`mixSeed(seed, salt)`），互不串味。
- 跨区块的树冠写入走「拥有者区块 → 邻居」的 outgoing / pendingIn 队列，
  **只填空气**，且树根间距 ≥ 7 列（> 2×最大树冠半径），保证树冠不重叠
  → 无论区块以什么顺序生成，最终逐格一致。

## 4. 参数表在哪

**所有生成参数集中在 `minecraft/worldgen/constants.js`**，没有一个魔法数字散落在别处：

| 区块 | 内容 |
|---|---|
| `WORLD_*` | 世界尺寸、海平面、渲染/卸载距离、生成预算、存档格式版本 |
| `NOISE` | 每种噪声的频率/倍频/持久度/ lacunarity/子种子 |
| `BLEND_RADIUS` / `CLIMATE_*` | 群系边界混合半径、气候低通滤波窗口 |
| `CAVES` | 蠕虫/大空洞阈值、竖井概率与深度、洞口概率、海水防漏护栏 |
| `ORES` | 每种矿的 Y 区间、尝试次数、矿脉大小（注释里标了 Java 1.20 的出处） |
| `WORLD_TYPE_PRESETS` | 默认 / 超平坦 / 巨大群系 三套预设 |

调参入口：
- **世界类型**：创建世界界面里选「默认 / 超平坦 / 巨大群系」，另有洞穴、结构两个开关。
- **单个矿的密度**：`ORES` 表里改 `perChunk2D`。
- **洞穴密度**：改 `CAVES.wormThreshold` / `cheeseThreshold`，改完跑一次
  `node tools/dev/mc_calib_caves.mjs` 看覆盖率是否还在目标区间。

## 5. 存档与版本

- **当前格式 v6**：头部记 `worldgenVersion` / `worldType` / `paletteHash` / `paletteLen`，
  正文只存**被玩家改动过的区块**（RLE 压缩）+ 稀疏流体表 + 流体队列。
  没被改动的地方按「同种子 + 同坐标」重新生成 —— 外观与存档时一模一样。
- **老存档 v1~v5**：整张扁平地图 → 以**覆盖层**方式贴回世界（只覆盖旧地图真正有的格子，
  其余格子照常生成 → 世界连续、不会出现悬空大洞腔）；竖直方向按「旧世界的底对齐新世界的底」
  翻转（v4/v5 是 256 高满世界，等价于逐格对应；最老的 144 高存档也能无缝接上）。
  读入后会在聊天栏明确提示「存档已从旧版本迁移」。
- **调色板只允许在表尾追加**：存档里存的是调色板下标，中间插入会让所有老存档整体错位。
  读档时若指纹不一致，先判断「存档里的调色板是不是当前调色板的前缀」：
  是 → 安全读取；否 → **明确报错**，绝不静默读错。

### 7.1 发布 / 构建

`minecraft/game.js` 是**唯一源码**，`index.html` 引用的是带哈希的产物 `game.<hash8>.js`。
改完 `game.js` 必须重新生成，否则浏览器加载的还是旧代码：

```
python tools/hash_assets.py
```

脚本会产出 `minecraft/game.<hash8>.js`、改写 `minecraft/index.html` 的 `<script src>`，
并同步 `_headers` 的缓存策略。`game.js` 里任何一行改动都会改变哈希，
交付前用 `cmp minecraft/game.js minecraft/game.<hash8>.js` 确认两者一致。
